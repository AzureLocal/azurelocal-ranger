## Access and permissions

WinRM to the nodes for VMs, certificates, BitLocker, Defender and Active Directory; Azure Resource Manager and Resource Graph with at least Reader on the cluster resource group. Read-only.

## Output

Top-level keys of each domain, as seen in the fixture manifest (`tests/maproom/Fixtures/synthetic-manifest.json`). Collectors can add keys between releases; the manifest schema keeps domain payloads open.

### `domains.virtualMachines`

`inventory`, `placement`, `replication`, `summary`, `workloadFamilies`

### `domains.identitySecurity`

`activeDirectory`, `auditPolicy`, `certificates`, `keyVault`, `localAdmins`, `nodes`, `posture`, `summary`

### `domains.azureIntegration`

`arcExtensionsDetail`, `arcGatewayNodeRouting`, `arcGateways`, `arcMachines`, `auth`, `backup`, `context`, `cost`, `costLicensing`, `customLocations`, `customLocationsDetail`, `extensions`, `galleryImages`, `marketplaceImages`, `policy`, `policySummary`, `resourceBridge`, `resourceBridgeDetail`, `resourceLocations`, `resources`, `resourceSummary`, `services`, `siteRecovery`, `update`

## When it is skipped, degraded or failed

Azure reads degrade (not fail) when ARM returns 403, 404 or throttling: the item is listed in manifest.run.skippedResources and in the collector degradations.

The collector status in the manifest is one of `success`, `partial`, `failed`, `skipped` or `not-applicable`. Since v2.7.0 the entry also carries `degraded`, `degradationCount` and `degradations` (source and message of every non-fatal read that failed), and a degraded collector adds an informational finding. Debug-level detail is in `ranger.log`.
